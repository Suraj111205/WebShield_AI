OWASP Top 10 Web Vulnerabilities Guide

Understand the 10 most critical security risks facing web applications today, with live detection badges dynamically updated when you scan your site.

A01:2021
Ready to Audit
Broken Access Control
Visitors viewing or modifying private pages (like /admin, /portal, or other users' profiles) because server permission checks are missing or weak.
Detection Method:
BFS link crawler identifies exposed administrative routes and unauthenticated path traversal attempts.
Remediation Guidance: Enforce strict role-based authorization on every route, and never expose administrative panels publicly.
A02:2021
Ready to Audit
Cryptographic Failures
Transmitting sensitive user data over unencrypted HTTP or using invalid, expired SSL/TLS certificates that allow eavesdropping on public Wi-Fi.
Detection Method:
Direct TLS/SSL socket handshake verification and RFC 6797 HTTP Strict-Transport-Security (HSTS) header parsing.
Remediation Guidance: Install a valid SSL certificate and add the Strict-Transport-Security header to force HTTPS always.
A03:2021
Ready to Audit
Injection (SQLi & XSS)
Attackers submitting malicious code or database commands into search boxes and forms, tricking the server into dumping data or stealing user session cookies.
Detection Method:
BeautifulSoup DOM form parser identifies unvalidated inputs, missing CSP restrictions, and insecure HTTP action targets.
Remediation Guidance: Always use Parameterized Queries (Prepared Statements) for SQL databases and set a Content-Security-Policy.
A04:2021
Ready to Audit
Insecure Design
Missing security architecture before building the site, such as lack of rate-limiting, allowing automated bots to guess passwords repeatedly.
Detection Method:
Heuristic form security analysis and response header inspection for anti-automation policies.
Remediation Guidance: Implement rate limiting, CAPTCHA on login forms, and secure password-recovery workflows.
A05:2021
Ready to Audit
Security Misconfiguration
Leaving default passwords, unneeded debug features, open directory browsing, or omitting modern defense headers like X-Frame-Options and CSP.
Detection Method:
HTTP response header rule-matching engine parses CSP, Clickjacking (X-Frame-Options), and MIME-sniffing (X-Content-Type-Options).
Remediation Guidance: Add standard security headers in Nginx or Apache, and turn off directory browsing in your web server configuration.
A06:2021
Ready to Audit
Vulnerable & Outdated Components
Running old web server versions or outdated CMS libraries that have publicly known vulnerabilities that automated scanning bots exploit.
Detection Method:
Passive Server & X-Powered-By header fingerprinting to detect revealed version numbers.
Remediation Guidance: Hide server banner info with `server_tokens off;` and regularly update server packages.
A07:2021
Ready to Audit
Identification & Auth Failures
Weak authentication mechanisms allowing credential stuffing, session hijacking, or forms sending login credentials across plain HTTP.
Detection Method:
Inspects login forms for insecure HTTP transmission, missing CSRF tokens, and unflagged session cookies.
Remediation Guidance: Ensure all login forms submit over HTTPS, use anti-CSRF tokens, and mark session cookies as HttpOnly and Secure.
A08:2021
Ready to Audit
Software & Data Integrity Failures
Loading JavaScript libraries or plugins from external CDNs without verifying their integrity hash, allowing third-party compromise.
Detection Method:
HTML tag scanner checks external script and style links for Subresource Integrity (SRI) cryptographic hash attributes.
Remediation Guidance: Add `integrity="sha384-..."` attributes when including third-party CDN scripts.
A09:2021
Ready to Audit
Security Logging & Monitoring Failures
Not recording security errors and login failures, meaning security breaches can go unnoticed for weeks or months.
Detection Method:
Audits server error status handling to verify that errors fail gracefully without leaking database stack traces.
Remediation Guidance: Set up central logging for suspicious HTTP codes (401, 403, 500) and failed authentication attempts.
A10:2021
Ready to Audit
Server-Side Request Forgery (SSRF)
Tricking your server into fetching remote URLs or communicating with private internal servers and cloud metadata endpoints.
Detection Method:
URL parameter heuristics parse query strings for parameters commonly used in SSRF attacks (e.g. `?dest=`, `?url=`, `?redirect=`).
Remediation Guidance: Use a strict domain allowlist for any server-initiated outbound HTTP requests and block access to 127.0.0.1.

Frequently Asked Questions

Clear explanations about WebShield AI scanner capabilities, non-destructive safety, and remediation steps.

What vulnerabilities does WebShield AI check for?
WebShield AI covers 15 automated security checks mapped directly against the 10 categories of the OWASP Top 10 standard. This includes Content-Security-Policy (CSP), Strict-Transport-Security (HSTS), X-Frame-Options (Clickjacking), X-Content-Type-Options (MIME sniffing), cookie security flags (HttpOnly & Secure), unencrypted HTTP login forms, missing Anti-CSRF protection tokens, technology banner leakage, and exposed backup archives (.env, .git, .bak).
Is scanning my website safe and non-destructive?
Yes, WebShield AI operates entirely via passive security inspection and benign crawling. It conducts header verification, DOM form parameter audits, and safe HTTP requests without deploying destructive denial-of-service or database-altering exploit payloads.
Do I need authorization before scanning a website?
Yes. In accordance with computer misuse legislation and our Terms & Conditions, you should only initiate scans against web properties that you own, operate, or have received explicit written permission to test.
How does the Breadth-First Search (BFS) crawler function?
The crawler utilizes a FIFO queue structure (Python deque) to systematically discover internal endpoints starting from depth 0 (homepage). It normalizes domains, respects crawl limits (up to 10 pages in Medium scan, up to 25 pages in Deep scan), and uses an O(1) visited hash set to eliminate circular loops.
What is the difference between Basic, Medium, and Deep scans?
Basic Scan checks the homepage surface in 2 to 5 seconds. Medium Scan traverses direct site links to inspect HTML forms and CSRF protection. Deep Scan executes multi-level crawl traversal, examines cookie flags, scans for exposed backup configurations, and synthesizes an executive PDF report.
Can I export audit results as an executive PDF report?
Yes. After running a Medium or Deep scan, click the "Download Executive PDF" button to download a formatted security report complete with CVSS ratings, discovered attack surface metrics, and specific remediation code snippets.
